# 18. Delivery & Launch QA Checklist

Run this checklist before asking for final approval. Tick every item in the project record.

## Content and conversion

- [ ] Business name, service names, pricing, address, and contact details are correct.
- [ ] Primary CTA is obvious on the first screen and repeated where useful.
- [ ] WhatsApp link opens the correct number with a useful pre-filled message.
- [ ] Click-to-call link works on a phone.
- [ ] Contact form sends a test submission to the agreed inbox.
- [ ] All client-provided images have useful alt text or are decorative.
- [ ] No placeholder text, lorem ipsum, dummy phone numbers, or unused sections remain.

## Mobile and browser checks

- [ ] Test at 360px, 390px, 768px, and desktop width.
- [ ] Test Chrome and Safari on a phone.
- [ ] Navigation opens, closes, and can be used with a keyboard.
- [ ] Buttons have comfortable tap targets.
- [ ] Text does not overflow horizontally.
- [ ] Reduced-motion preference does not hide important content.

## Technical and SEO checks

- [ ] HTTPS is active on the client domain.
- [ ] Favicon, title, description, canonical URL, and social preview are present.
- [ ] `robots.txt` does not block the live site.
- [ ] Sitemap and Google Search Console ownership are connected where included in scope.
- [ ] Local business schema uses the client's approved name, phone, address, hours, and service area.
- [ ] Analytics is connected to the client's property where included in scope.
- [ ] Every internal link resolves.
- [ ] Images are compressed and lazy-loaded below the fold.

## Handover

- [ ] Client has approved the live URL.
- [ ] Source repository and deployment access are documented.
- [ ] Domain registrar and hosting ownership are clear.
- [ ] Final balance is received.
- [ ] Handoff message sent.
- [ ] 30-day support start date recorded.
- [ ] Review request sent after the client confirms satisfaction.
