A designer and a developer are not interchangeable, and most Pune businesses that hire the wrong one find out about two months later, after paying for the wrong deliverable.

This guide explains the actual difference between UI/UX design and web development, what each produces, what each costs in Pune, and how to hire without confusing them.

## The One-Sentence Difference

**Design decides what the screen looks like and how it behaves. Development decides how it actually works.**

A designer produces a Figma file. A developer produces a running application. Neither is complete without the other - which is exactly why the scope needs to be defined before anyone starts.

## What Each Deliverable Contains

### UI/UX Design Deliverable

| Artifact | What it is |
|---|---|
| User flows | The path a real user takes through each task |
| Wireframes | Low-fidelity structure, no visual styling |
| High-fidelity mockups | Pixel-accurate screens, desktop and mobile |
| Design system | Type scale, colour tokens, spacing rules, components |
| Interactive prototype | Clickable Figma prototype demonstrating flow |
| Accessibility spec | Contrast ratios, tap target sizes, focus states |
| Handoff documentation | Specs, assets, and states for engineering |

### Web Development Deliverable

| Artifact | What it is |
|---|---|
| Working application | Runs on real infrastructure, not a prototype |
| Responsive implementation | Correct across device sizes |
| Database and backend | Schema, queries, migrations |
| Authentication | Secure login, sessions, role-based access |
| API integration | Third-party services connected |
| CMS or admin | So content can be edited without a developer |
| Test coverage | Automated tests for critical paths |
| Deployment pipeline | CI/CD, staging, monitoring |
| Documentation | How to run, extend, and maintain it |

**The critical distinction:** a Figma prototype demonstrates that a design is *plausible*. A working application demonstrates that it is *viable*. Only one of those is a product.

**The pattern to notice:** design-only is roughly 25-35% of design-and-build cost. If someone quotes you design-only and then you hire a developer to implement it, you pay for re-interpretation of a Figma file. That re-interpretation is real work and it is where scope disputes begin.

## When You Need Design Only

Choose design-only when the output is not being built in-house by your team:

- **You have an internal engineering team** with the capability to implement from a Figma file
- **You need to validate a concept** before committing build budget
- **You are redesigning a product your developers already maintain**
- **You need a design system** for an existing multi-product organisation

If you do not have the team to implement it, design-only work will sit unused. Ask who is building it before you commission the design.

## When You Need Development Only

Choose development-only when the design is already decided:

- **You are rebuilding on a new framework** with the same design
- **You are migrating platforms** - WooCommerce to Shopify, WordPress to headless
- **You have an in-house designer** producing specs
- **You are fixing performance** on an existing, adequately designed site

## When You Need Both

This is the majority of Pune projects:

- A new marketing site with no existing design
- A redesign where the current design is not worth preserving
- A new product or web application
- Anything where you need both a strategy and a working result

The advantage is accountability. One team owns both, and the design cannot drift from what gets built.

**The disadvantage is worth naming:** you cannot evaluate the design until late in the process, which is uncomfortable if you dislike the direction.

The mitigation is a staged process. See below.

## The Mistakes That Cause Budget Overruns

**1. Designing features that cannot be built.**
Animation that requires impossible layout. A colour palette that fails WCAG contrast. Interaction patterns with no accessible keyboard equivalent. WCAG 2.2 Level AA is now the ISO standard, so this is not optional polish - it is a deliverable requirement.

**2. Designing screens without designing states.**
What does the form look like while submitting? On error? Empty? Loading? Most Pune budget disputes trace back to states nobody drew and nobody quoted.

**3. Changing the design after development starts.**
Every mid-build design change is a change order. Either lock the design, or budget a change-request process.

**4. Handing off a Figma file nobody can implement.**
Figma auto-layout and component structure do not translate cleanly to code. A design built with proper constraints is materially cheaper to implement than one that is not.

**5. Treating design as decoration.**
If your designer has not asked how you make money, they have designed a brochure, not a conversion surface.

## A Process That Avoids the Traps

**Stage 1 - Discovery (2-5 days).** Business model, customers, what the site must do, technical constraints, budget reality. Output: a scope document.

**Stage 2 - Wireframes (1 week).** Low-fidelity structure for every page and flow. Cheap to change, catches structural problems while they are still cheap to fix. This is where most projects should spend more time than they do.

**Stage 3 - High-fidelity design (1-2 weeks).** Visual design across desktop and mobile, plus every state.

**Stage 4 - Design system and handoff (3-5 days).** Tokens, components, specs. This is what makes development predictable.

**Stage 5 - Build in sprints.** See working software every two weeks. A sprint of work you did not want is a sprint of money you did not need to spend.

**Stage 6 - QA against the design, accessibility, and performance.**

Total for a 6-12 page site: 4-8 weeks. Anything claiming 7 days for design and build of the same scope is producing something you will pay to fix.

## Questions to Ask Either Kind of Vendor

**To a designer:**
1. Do you start with wireframes, and will I see them before high-fidelity design?
2. Have you designed every state, not just the happy path?
3. What are your accessibility targets - specifically WCAG 2.2 AA?
4. Will the deliverable be a usable design system or a set of static screens?
5. Who at my company is implementing this, and do they have the capability?

**To a developer:**
1. Which framework and version, and will I own the source code?
2. What are your target Core Web Vitals on a mid-range Android?
3. How do you handle error states, empty states, and loading states?
4. What testing do you write, and does CI run it?
5. What does the admin or CMS look like - or who edits content after launch?

## Frequently Asked Questions

**What is the difference between UI and UX design?**
UI is the visual layer - layout, colour, typography, components. UX is the whole experience - the journey, the flows, whether the user can accomplish their task. Good UX with plain UI is usable. Good UI with bad UX is decoration.

**Do I need a UI/UX designer if I have a good developer?**
Not strictly. Many senior developers produce competent interfaces. But a good developer who is also a good designer is rare, and you are paying for one skill while hoping for two. If your developer is strong on architecture and weak on visual design, a short design engagement covers the gap.

**How much does UI/UX design cost in Pune?**
₹30,000-₹70,000 for a 6-12 page marketing site design. ₹40,000-₹90,000 for a dashboard or internal tool. ₹80,000-₹2,00,000 for a full custom application design. Our [full Pune cost breakdown](/blog/website-design-cost-pune-2026) covers all tiers.

**Should I hire a designer or an agency in Pune?**
A designer for focused, single-project design work. An agency for multi-service needs - branding, content, SEO, ongoing iteration. The deciding question is whether you need one specialist or several.

**Is Figma still the standard tool in 2026?**
Yes, and it has become more capable rather than less. Figma's 2026 AI features now handle layout variations, wireframe generation, and accessibility audits, while its configuration platform added Agent Skills and generative plugins. Figma's own research found designer participation in development doubled to 41% - the boundary between design and build is genuinely thinner now.

**How long does design take before development starts?**
Two to four weeks for a marketing site. Longer for a custom application. Wireframes alone should take at least a week for anything substantial.

The expensive mistake is hiring a developer to make design decisions, or a designer to make architecture decisions. Both happen regularly in Pune and both produce work that needs redoing.
